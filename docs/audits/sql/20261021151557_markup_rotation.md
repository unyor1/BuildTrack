## Purpose

Photo markup can be rotated in the editor. Each mark may carry an optional numeric `rotation`: degrees around the mark's own centre.

## Objects changed

| Object | Change |
|---|---|
| `valid_issue_markup(jsonb)` | `create or replace`, same signature: immutable, invoker, `search_path=''`. A mark may now have 11 keys, as before, or 12 where the 12th is `rotation`, a number from -360 to 360. Any other extra key, a missing required key or a non-numeric / out-of-range rotation is refused. All other rules are unchanged: 150 marks, 500 points, 0-100% coordinates, `#rrggbb` colour, stroke 1-12, font 12-72, non-blank text. The function keeps its OID, so the check constraints on `snag_photos`, `site_issue_photos` and `qa_photos` and the `insert_site_issue_photos` / `save_site_issue_photo` RPCs use the new rule without being recreated. |
