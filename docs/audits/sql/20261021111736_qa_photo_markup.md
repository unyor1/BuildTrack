## Purpose

Engineers (and Foremen preparing a requested inspection) can mark up inspection and NCR evidence photos before adding them, with the same editor as client problem reports and site issues. The file stays the original; the markup is stored beside it.

## Objects changed

| Object | Change |
|---|---|
| `qa_photos.annotations` | New `jsonb not null default '[]'`, `check (public.valid_issue_markup(annotations))`: the same 150-mark / 500-point / 0-100 % coordinate / colour / size rules as `snag_photos` and `site_issue_photos`. Existing rows get `[]`. |
| Grants | `insert (annotations)` to `authenticated`. No UPDATE grant exists on `qa_photos`, so markup is fixed once the photo is recorded, like the rest of the evidence. |

## Security and RLS

No policy change: the existing insert policy (`can_report_on_project`, `uploaded_by = auth.uid()`), the `check_qa_photo` trigger (inspection requested / in progress, NCR not closed, file inside the project folder), the submitted-work guard and the photo stamp trigger all apply unchanged. Clients still read no QA photos. Security advisors after applying: the same pre-existing findings, nothing new (no function, table or policy was added).
