## Purpose

Records on the blueprint must point at the right pin and, where it applies, the checklist item, by permanent id. Most records already did:
- site issues: `pin_id`, `checklist_item_id`, `checklist_name`;
- client reports and questions: `pin_id`;
- inspections: `pin_id`, `work_item_ids`;
- daily reports: `linked_work`;
- photos: `pin_id`, `checklist_item_id`, `qa_attempt_id`.

Two gaps are closed here:
- An NCR raised directly could not name its checklist item.
- The assigned Foreman had no way to report a field problem that reaches the Engineer.

## Objects changed

| Object | Change |
|---|---|
| `qa_defects.checklist_item_id` | New, `references pin_checklist_items on delete set null`, indexed. |
| `qa_defects.checklist_name` | New. The item's name when the NCR was raised; kept when the item is renamed or removed. |
| `guard_defect_links()` + trigger `qa_defects_links` | Before insert / update of `pin_id`, `checklist_item_id`, `project_id`. It refuses a pin of another project and an item of another pin or project. It takes the pin from the item when only the item is given, and saves the item name. When the pin is removed, the item link goes with it and the name stays. Not executable by API roles. |
| `raise_defect(…, p_checklist_item uuid)` (11 arguments, no defaults) | Same checks as before, plus the item check. Security definer; `authenticated` only. |
| `raise_defect(…)` (old 10 arguments) | Now a `security invoker` SQL wrapper that calls the 11-argument form with no item. `decide_snag` and older clients keep working; the grants are unchanged. |
| `report_field_problem(p_pin, p_item, p_note)` | New. Only the assigned active Foreman of the pin (`can_work_on_pin`). Note 5–1000 characters, item of the same pin, at most 20 a day. It writes a `comment` on the pin timeline (`Field problem: [item] …`) and notifies each project Engineer (`pin.problem`, link to the pin's Activity). It creates no NCR and changes no status. |

**Unchanged on purpose:**
- `item_defect_ids`, the correction package, `review_checklist_item` and `try_complete_work` are untouched.
- An NCR raised from an inspection keeps its link through the inspection.
- A directly raised NCR still blocks completion of its work pin, as before, and is corrected through the NCR itself.

## Security and RLS

No policy change:
- `qa_defects` stays read-only to the API (staff read through the existing policy; clients never read it).
- A direct `update` of the new columns by an Engineer is refused.
- Who may raise an NCR is unchanged (`can_report_on_project`).
- Field problems are limited to the assigned Foreman. Engineers of other projects are not notified.

Security advisors after applying:
- 4 info, 1 auth, as before.
- 91 warn instead of 90. The two new signed-in-only definer RPCs (`report_field_problem`, the 11-argument `raise_defect`) join the existing list, and the 10-argument `raise_defect` left it (now invoker).
