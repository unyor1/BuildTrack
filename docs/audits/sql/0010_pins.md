## Purpose
The core feature: pins on a blueprint that track site progress and quality. Position is stored as a percentage of the plan image (0-100), so it stays accurate at any zoom and on any screen.

## Objects
| Type | Name | Notes |
|---|---|---|
| Enums | `pin_status` (not_started, in_progress, for_review, issue, verified), `pin_category` (progress, quality, safety, note) | |
| Table | `pins` | x/y (0-100), title, description, category, discipline, status, assigned_to (a Foreman on the project), due_date, created_by, verified_by/at |
| Table | `pin_events` | timeline: created, moved, edited, status, comment, photo. Written by triggers or as comments; immutable |
| Table | `pin_photos` | photo rows (files live in storage) |
| Functions | `report_pin_progress(pin, status, note)`, `is_project_client`, `can_report_on_project` | |
| Triggers | `prepare_pin` (project from blueprint, creator, verified_by/at, assignment validation, no moving to another plan), `record_pin_events`, `prepare_pin_event`, `prepare_pin_photo`, `record_photo_event`, `pins_audit` | |
| Bucket | `pin-photos` | private, 8 MB, JPEG/PNG/WebP |

## Access rules
| Action | Who |
|---|---|
| See pins and photos | everyone assigned to the project incl. Client (read-only), admins with `projects.manage` / `blueprints.manage` (MFA) |
| Create / edit / move / delete pins, set Verified or Issue | Engineers assigned to the project; admins with `blueprints.manage` |
| Delete a VERIFIED pin | admins with `blueprints.manage` only |
| Report progress (In progress, For review) + optional note | Foremen assigned to the project, through `report_pin_progress` only (cannot edit pins directly; not on verified pins; not on pins assigned to another Foreman) |
| See the timeline | Engineers, Foremen, admins; NOT Clients or outsiders |
| Comment | Engineers, Foremen, admins with `blueprints.manage`; who and which project are set by the database; entries cannot be edited or deleted |
| Add photos | same as commenting; delete: uploader or admin with `blueprints.manage` |

## Tests (`supabase/tests/30-pins.cases.mjs`)
Pin creation defaults and events; project_id spoofing; invalid coordinates/title/revision; outsiders/pending/anon blocked; client read-only; foreman cannot edit directly; moved/edited events; no cross-plan moves; assignment rules; foreman reporting rules and limits; verification and un-verification; verified-pin delete rules; timeline privacy; comment rules and actor spoofing; immutability; photo rules; pin-photos storage rules; cascades; audit.

## Verification (done on the live project)
Rolled-back transaction as Super Admin: project -> blueprint -> revision (client sent 77, stored 1) -> pin -> verified (verified_by = caller) -> comment -> photo: 4 timeline entries, 1 photo, nothing left behind.
