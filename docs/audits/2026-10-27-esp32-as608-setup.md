Date: October 27, 2026 (Asia/Manila).

Exact sensor variant/supply and physical wiring were not supplied. This work assumes the classic DOIT ESP32 DEVKIT V1/WROOM pinout, explicitly documented for review before wiring.

Read the existing hardware README, attendance and legacy enrollment sketches, example configuration, attendance/enrollment handlers, current project handover and relevant upstream UART/library documentation.

## Implementation

- Added `connection_test/connection_test.ino`: explicit HardwareSerial UART2 RX16/TX17 at 57600, serial monitor at 115200, default sensor password, password/parameter/template-count handshake, automatic retry and reconnect/info/help commands. Startup and each scan require a finger lift. Captures and searches the module's reported capacity; errors distinguish communication loss from an unmatched finger. No persistent sensor modifications, enrollment, deletion, raw-template export, Wi-Fi or attendance submission.
- The diagnostic uses the library's Stream constructor so only the sketch initializes UART pins, and waits for sensor startup. It rejects non-classic ESP32 compilation to avoid silently reusing this board's pinout.
- Attendance firmware now compiles against `config.example.h` if private config is absent. Existing runtime checks stop execution with placeholder credentials and give setup instructions. A real private config still takes precedence.
- Attendance search now uses `fingerSearch(1)`, which searches the capacity returned by `getParameters()`, in place of the library's fixed-range `fingerFastSearch()`. Receiver payloads and enrollment authorization/persistence are unchanged.
- Added `FIRST_UPLOAD.md`: concrete installed setup, crossed UART wiring, module-specific power requirements, actual USB port discovery, Verify/Upload/BOOT/monitor steps, expected output, transition to existing Admin-controlled enrollment and explicit IN/OUT operation. No manual enrollment IDs or new web UI.
- Updated hardware README and `codex.md` with the starting point and physical-test limits.

## Follow-up: private single-file sketch

The user reported the local scanner test working on 3.3 V. Later compilation logs showed they copied attendance code into `Documents/led/led.ino` and then an unsaved Arduino sketch without either required configuration header. They requested a new sketch.

- Added local `hardware/esp32-as608/private_upload/buildtrack_as608/buildtrack_as608.ino`, with all configuration in the sketch. It has no private/example header include. The entire private_upload directory is ignored by Git and the sketch is not tracked. Existing user Wi-Fi/device settings are embedded without printing them or adding them to public documentation.
- Reused the existing attendance/enrollment implementation; added non-secret startup/wait messages and enrollment HTTP status diagnostics. Durable event/result storage, explicit IN/OUT, Admin enrollment and certificate validation remain.
- Completed the missing public CA setup for this new sketch. A Windows SslStream handshake validated the live project host with normal hostname/certificate validation; X509Chain validation succeeded. The chain ended at GlobalSign ECC Root CA - R4 (thumbprint `6BA0B098E171EF5AADFE4815807710F4BD6F0B28`). Downloaded the public bundle from [Google Trust Services](https://pki.goog/roots.pem) and embedded only the matching root certificate. No certificate-validation bypass or device credential was sent during these checks. This verifies the PC-to-server chain, not yet an ESP32 TLS session.
- New sketch compiled successfully (exit 0) for `esp32:esp32:esp32doit-devkit-v1`: 1,067,432 bytes flash (81%) and 49,024 bytes global RAM (14%). Compiler emitted an address-comparison warning after constant-folding the `strstr` certificate-presence guard against the now-populated certificate; it is not a missing-header or build failure. Verified the saved file matches the constructed source and has no config-header include. Git ignore checks passed.
- No firmware upload, enrollment, attendance write, Git commit or push was performed. The separate private config and original sketch remain available; this new file is a snapshot, not a generated-on-build dependency.

**Correction (later on 2026-10-27):** the embedded root above was wrong for the ESP32. The server sends supabase.co → WE1 → GTS Root R4 cross-signed by GlobalSign Root CA (RSA), not by GlobalSign ECC Root CA - R4; Windows had built a different path. On the device every enrollment request failed with HTTP -1 and the server never saw it. Fixed with a three-root bundle; see [fingerprint registration steps](2026-10-27-fingerprint-registration-steps.md).
